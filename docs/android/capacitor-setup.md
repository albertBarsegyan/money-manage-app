# Capacitor setup and synchronization

## Project configuration

The repository already includes `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/app`, and `@capacitor/splash-screen` (Capacitor 8). `capacitor.config.ts` sets:

- `appId`: `com.finora.app` — keep stable after Play listing creation.
- `appName`: `Finora`.
- `webDir`: `out` — generated by `npm run build:mobile`.
- Background, splash, and system bar presentation.

Production builds bundle local web assets. Do not set `server.url` for production; a remote URL changes delivery and offline behavior and would require a separately approved architecture decision.

## Commands

Run from the repository root with dependencies installed:

```bash
npm run build:mobile
npx cap sync android
```

The convenience script combines both operations:

```bash
npm run android:sync
```

To open the project in Android Studio:

```bash
npm run android:open
```

After changing web assets or Capacitor plugins, run `npm run android:sync` again. `cap sync` copies web output and updates native plugin dependencies; it does not build a signed release.

## Web versus mobile builds

`npm run build` is the normal Next.js web production build. `npm run build:mobile` uses `scripts/build-mobile.mjs` to generate routes and set `FINORA_BUILD_TARGET=capacitor` for a separate static export. This distinction preserves the existing web runtime. The export lists `/`, `/transactions`, `/income`, `/accounts`, `/salary-periods`, `/analytics`, `/integrations`, and `/settings` for client-side routing.

## Adding Capacitor packages

Use official Capacitor plugins when they meet a real product need. Install a compatible major version and sync Android after installation:

```bash
npm install @capacitor/network
npm run android:sync
```

Do not install an example plugin just to enable a capability that the product does not use. Check the Android permission and privacy effects before adding a plugin.
